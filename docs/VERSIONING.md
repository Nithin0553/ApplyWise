# Versioning and Change Control

Use semantic repository versions: `MAJOR.MINOR.PATCH`.

- 0.1.0 foundation
- 0.x integrated development releases
- 1.0.0 approved course release

Formal course documents keep their own revision histories.

Any change to scope, approved feature behavior, priority/precedence, grounding rules, security/access, or quality targets should be tracked as a change request and reviewed by the responsible managers.

Record changes in GitHub Issues, Pull Requests, ADRs when architectural, `CHANGELOG.md` when release-visible, and formal document revision history when that artifact changes.
